# SCRM Business Lines Records Framework

Scope: GitHub Issue #22. The shared typed schema, dialogs, policy resolver, preferences, and transfer jobs are introduced for Business Lines first. Other modules keep their existing behavior until they declare their own schema, actions, and authorization. This release does not grant additional CRM access.

## User workflows

### Column Selection and Column Customization

**Customize > Column Selection** offers Default View, My View, All Columns, column search, four collapsible groups, group selection, Select All and Clear Optional. Business Line ID and Name cannot be deselected. Apply View persists the active preset and current selection; Save as My View replaces the personal preset. Preferences are stored by actual user ID and module in PostgreSQL, not just browser storage. Column widths, page size, filters, sorting, separate Records/Overview contexts and section collapse state are remembered.

**Customize > Column Customization** is Super Admin only. Drag rows or use accessible Up/Down buttons to establish the common sequence. Configure 0-5 frozen leading data columns, additional always-selected columns, and the All/default column pools for Super Admin, Admin, Manager and Standard User. All nineteen fields are permanently in Super Admin's All pool. Preview the configured role's defaults before saving. Save Draft never changes the effective policy; Publish validates and increments its published revision. Configuration changes are audited and cannot remove mandatory Create/Edit fields. Policies narrow presentation; they do not replace or expand backend security permissions.

### Search, filter, sort and selection

Live search and typed filters query the entire authorized dataset. Quick status/record-state controls coexist with the advanced AND/OR builder. Up to 20 conditions, three group levels, and five sort priorities are supported. Date-only filter values use UTC boundaries; date displays use the browser locale. Text wildcard characters are treated literally. Saved filters and per-view contexts can be restored.

Click a column header for a primary sort; Shift-click adds a secondary sort. The Sort Order dialog offers the same controls on mobile and supports priority changes. Sorting uses a stable record-ID tiebreaker. Table headers wrap, resize, and remain sticky. The Actions column stays at the right. Frozen leading columns are capped dynamically so narrow viewports retain scrollable content. Descriptions expand only for the requested record. Mobile uses responsive record cards and page selection.

Selection begins with the current page. Selecting all matching results is a separate explicit action displaying its count. Changing the query/sort clears selection. Bulk actions show a reviewed count and mandatory reason, snapshot record IDs/versions, then revalidate every record's permissions, dependencies and version. Partial failures are reported rather than silently overwritten. Permanent deletion is never offered.

### Import

1. Download the module's CSV or Excel template. New-record templates contain Code, Name and Description only; Business Line ID is generated by the system. Excel includes a Guidelines sheet. CSV has a separate downloadable guidelines file with every supported field, required value, dependency, matching rule and default.
2. Upload UTF-8 CSV or XLSX. Maximum **2 MB / 10,000 rows / 64 columns**. Macro-enabled files, formulas, unsafe archives and oversized cells are rejected.
3. Map Name and Code (required), plus optional Description. Update/Upsert can additionally map an existing Business Line ID for matching; this never sets a new ID. System metadata, owner and lifecycle state are not importable.
4. Choose Create Only, Update Existing, or Upsert, subject to the existing backend permissions. New records default to Active with the current owner and audit metadata.
5. Choose all-or-nothing (**maximum 250 rows**) or explicitly choose partial processing for larger files. The conservative atomic limit protects the production serverless execution budget.
6. Follow the gated wizard: Choose file → Match columns → Review and confirm → Import and results. Upload and validation do not change CRM records. Review the preview, duplicate errors, missing fields and match results. Each validation issues a fresh review token; a changed mapping or another tab's revalidation requires a new review before confirmation.
7. Confirm & Import becomes available only after the review allows it. For mixed-validity files, Import valid rows only revalidates the proposal and still requires this final confirmation. Already committed rows never repeat on Resume. An exact file reupload within the retained job lifetime explicitly opens the original outcome and states that no new records were imported.
8. Review Created, Updated, Unchanged and Failed totals. Unchanged rows do not create writes or new audit events. Download failed rows for correction or the full row-outcome report, then upload a corrected file. Unmapped Description is preserved on updates; mapped blank Description clears it. Archived/deleted matches require separate restoration. All-or-nothing execution rolls back all rows on any runtime conflict.

Name: normalized whitespace, case-insensitive uniqueness, 150 characters. Code: uppercase letters/digits/hyphens, 20 characters, globally unique across lifecycle states. Description: optional multiline, 500 characters. Code remains editable through authorized updates; system IDs are not renumbered.

### Export

Record scope and column scope are separate decisions. **Current Page is the safe initial record scope.** Alternatives: checked records, all matching results, all authorized records with explicit confirmation, or export-specific filters. Column presets: current displayed, role default, My View, all permitted, or custom selection. Default View never means every database record.

Review the exact count and columns before confirmation. Custom columns are grouped by field section. CSV and XLSX are generated as resumable jobs. The maximum is **500,000 records**, split into ordered files of **up to 1,000 rows**; wide content is split into smaller parts automatically to stay within the 2.5 MB part limit. A single oversized record produces an actionable error. Each download is authenticated, expires 24 hours after job completion and revalidates the published column policy. Membership and order are snapshotted when the job is confirmed; field values are read when that part is generated. Records removed since confirmation are reported as skipped. Saved job details describe the effective selection; All and Selected do not claim unrelated table filters were applied.

Excel styles only the populated table, with borders, frozen headers, filters and bounded content-aware column widths. Numeric values and date cells retain their spreadsheet types; identifiers and codes remain literal text. Date columns have adjacent Time Zone columns. Export Details explains the selection, time conversion and formatting. CSV contains readable UTF-8 values and separate timezone columns, with a companion guidelines download; CSV cannot store workbook styling, types or extra sheets. Formula-like CSV text is neutralized. Timestamped filenames use filesystem-safe date/time separators and numbered parts.

Overview uses a context-sensitive toolbar. Its export downloads the filtered summary metrics, not every underlying record. Import and column-only customization are not displayed in Overview. Add remains available in the title area when permitted.

### Transfer recovery

Open **Import/Export History** from the top of a transfer popup. Its Import, Export and All tabs filter your own jobs. Inspect original settings, Resume a paused job, download highlighted file parts/reports, or cancel remaining work. Closing the popup and navigating to another module does not undo committed batches or stop normal generation. Work continues through bounded authenticated background invocations. Progress includes a measured estimate once sufficient processing data is available; paused jobs do not claim to be continuing. History and status read failures remain visible and offer retry.

Downloads stop exactly at expiry, while history still explains the result. Expired raw rows/file bytes are removed during transfer activity or the next authenticated daily maintenance sweep. The sweep also resumes a bounded set of stale jobs. If the hosting service interrupts continuation, History offers Resume; an expired export must be generated again.

### Dates and origin zones

Business Line timestamps remain absolute UTC instants. For new create, edit, owner/status and lifecycle actions, the browser supplies its IANA time zone as request context. Each successful write retains that zone in the append-only record event under `changes._context.timeZone`. Original Created events remain unchanged by later edits. No-op writes append no new event. Missing client zones and historical events remain unknown; the server never substitutes its own zone or a later reader's zone.

Import validation binds the browser zone to the reviewed job together with its validation token. Bulk confirmation stores the initiating browser zone with the queued job. Background workers and resumed jobs forward that saved zone to each record write; a Resume request cannot replace it. History returns `timeZone` separately and removes reserved context from the visible field-change list. This adds durable provenance without a database migration or extra ordinary form fields.

Export date cells use the export job's separately chosen conversion zone, with an adjacent IANA zone and per-instant UTC offset for each date column. These columns describe the exported local time, rather than claiming to be the original event zone. The Export Details sheet and CSV companion guide explain the distinction. Export summaries retain the effective record filters and sort order: selected IDs and All Authorized Records do not inherit irrelevant list filters, and only Current Page retains pagination limits.

## Architecture and security

- `records-schema.mjs`: one nineteen-field typed manifest, safe filter compiler and stable multi-sort.
- `records-policy.mjs`: immutable identity rules, presentation role pools, draft/publish CAS, database-backed user preferences.
- `records-files.mjs`: bounded CSV/XLSX parsing, spreadsheet safety, template and output generation.
- `records-jobs.mjs`: owned jobs, exact-file/request idempotency, validation, snapshots, savepoint rollback, batched processing and reports.
- `records-worker.mjs`: signed, timestamp-bounded background continuation using Vercel `waitUntil`. Every batch reloads its actual owner and permissions.
- `records-maintenance.mjs`: authenticated expiry cleanup and bounded stale-job recovery.
- `time-zone.mjs`: validates optional event-origin IANA timezone metadata without inventing unknown historical zones.
- `records-framework.mjs`: authorized routes and field-projected table responses; existing Create/Read/Edit/lifecycle rules are preserved.
- `records-tools.js/css`: reusable dialogs and Records presentation activated only by capability metadata.

Existing verified/approved Super Admin module eligibility remains unchanged. Ordinary Admin/Manager/Standard profiles can be configured for future column presentation but gain no new CRUD or export access. The server, not hidden buttons, governs access. Session, CSRF, origin, rate limits, immutable UID/BL IDs and lifecycle reasons remain enforced. UI draft values survive failure; validation appears inline and in a focusable summary.

## Deployment and recovery

The initial framework installation requires `007_records_framework.sql`, applied only after a fresh Neon recovery branch and an isolated repeat-migration check. That migration is already part of this refinement's baseline. **The popup/import/export refinements require no new database migration.** Source-zone provenance uses existing append-only audit JSON. Configure a private production `CRON_SECRET` of at least 32 characters for `/api/internal/records-maintenance`; `vercel.json` schedules it daily at 03:17 UTC. Deploy the tested commit to the existing SAICRM Vercel project and verify the production alias and maintenance authentication. If application rollback is needed, return Vercel to the preceding deployment; additive framework tables can remain while investigating. Do not drop imported production records or audit history to roll back UI code.

Required verification: unit/security tests, real PostgreSQL integration tests, legacy browser regression, the new framework browser workflow, and production build/alias/runtime checks. The tests cover upload dry-runs, partial and atomic imports, exact-file/request retry, real XLSX files, ordered multipart export, published-policy invalidation, authenticated denial, preference conflicts, nested filters, bulk snapshots, nineteen-field preservation, mobile cards and layout geometry.
