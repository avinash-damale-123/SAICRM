# Password recovery
The login page's Forgot password flow requests a real six-digit email code (POST /api/auth/forgot with method=otp), then accepts that code and a new password on the same site. Codes expire after 15 minutes, are keyed-hash stored, allow at most five wrong guesses, are consumed transactionally once, and are replaced by resend. Successful reset revokes every session. UI resend is delayed 60 seconds after a resend; server email/IP limits remain authoritative. Codes never appear in API responses, URLs, logs or browser storage.
Legacy single-use reset links remain supported by the API and existing fragments for compatibility; callers without a method retain the existing link flow. Link and OTP requests replace the same reset challenge, invalidating the previous credential. Do not copy reset credentials between preview and production.
The reported redirect came from a reset request recorded in the isolated preview database, not production. Its preview-domain link led to Vercel authentication. Use https://saicrm.vercel.app for real accounts; the preview has separate accounts and sessions.
Regression coverage checks concurrent consumption, resend replacement, expiry, guess limits, account isolation, session revocation, response privacy, and mobile OTP form behavior. Live delivered OTP still needs the user's final reset confirmation after rollout.
